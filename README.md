## Управление таблицами

Запуск: `database`

| Команда | Описание |
|---|---|
| `create_table <имя> <столбец:тип> ...` | создать таблицу (типы: `int`, `str`, `bool`; столбец `ID:int` добавляется автоматически) |
| `list_tables` | показать список таблиц |
| `drop_table <имя>` | удалить таблицу после подтверждения|
| `help` | справка |
| `exit` | выход |

Метаданные таблиц хранятся в файле `db_meta.json`.

## CRUD-операции

Данные каждой таблицы хранятся в файле `data/<имя_таблицы>.json`.

Правила ввода:
- строковые значения пишутся в кавычках: `"Sergei"`;
- логические значения пишутся как `true` или `false`;
- `ID` не вводится, он генерируется автоматически (максимальный ID + 1);
- все остальные поля обязательны.

| Команда | Описание |
|---|---|
| `insert into <таблица> values (<знач1>, <знач2>, ...)` | создать запись |
| `select from <таблица>` | прочитать все записи |
| `select from <таблица> where <столбец> = <значение>` | прочитать записи по условию |
| `update <таблица> set <столбец> = <значение> where <столбец> = <значение>` | обновить записи |
| `delete from <таблица> where <столбец> = <значение>` | удалить подходящие записи после подтверждения|
| `info <таблица>` | информация о таблице |

## Обработка ошибок

Для обработки ожидаемых ошибок используется декоратор
`handle_db_errors` из модуля `src/primitive_db/decorators.py`.

Он перехватывает:

`KeyError` - например, обращение к отсутствующему столбцу;
`ValueError` - ошибки валидации и некорректные значения;
`FileNotFoundError` - отсутствие файла, если исключение не было
обработано функцией работы с хранилищем.

При обработанной ошибке выводится сообщение, а обёрнутая функция
возвращает `None`.

Отсутствие файлов при первоначальной загрузке обрабатывается отдельно:
для метаданных возвращается пустой словарь, для данных таблицы -
пустой список.

## Подтверждение удаления

Декоратор `confirm_action(action_name)` запрашивает подтверждение
перед удалением таблицы или записей.

Пример:

```text
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]:
```

Для выполнения операции нужно ввести ровно `y`.
Любой другой ответ отменяет операцию. При отмене данные не изменяются.

## Измерение времени

Декоратор `log_time` измеряет время выполнения функций `insert`
и `select` с помощью `time.monotonic()`.

Пример вывода:

```text
Функция select выполнилась за 0.000 секунд.
```

Время выводится с тремя знаками после запятой.
Для быстрых операций значение может округляться до `0.000`.

Измеряется выполнение функций в `core.py`.
Загрузка и сохранение JSON-файлов, выполняемые отдельно в `engine.py`,
в этот замер не входят.

Если функция вызывает исключение, сообщение о времени в текущей
реализации не выводится.

## Кэширование выборок

Функция `create_cacher()` возвращает функцию
`cache_result(key, value_func)`, которая хранит словарь кэша
в замыкании.

При первом обращении по ключу вызывается `value_func()`,
а результат сохраняется. При повторном обращении возвращается
сохранённое значение.

В операции `select` ключ учитывает содержимое таблицы и условие запроса.
При изменении данных формируется другой ключ, поэтому последующая
выборка получает актуальный результат.

Результаты копируются с помощью `deepcopy`, чтобы изменение возвращённых
записей не меняло содержимое кэша.

Кэш хранится только в памяти текущего процесса. Чтение JSON-файлов
не кэшируется. Размер кэша не ограничен, а формирование ключей
и копирование данных требуют дополнительных ресурсов, поэтому
ускорение не гарантируется.
