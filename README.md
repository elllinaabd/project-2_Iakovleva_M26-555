# Primitive DB

Консольное приложение, имитирующее простую базу данных.

Позволяет создавать и удалять таблицы, добавлять, читать, обновлять
и удалять записи. Метаданные таблиц и записи сохраняются в JSON-файлах.

Проект реализован в процедурном стиле, без классов.

## Требования

- Python 3.12 или новее.
- Менеджер проектов uv.

## Установка

Клонируйте репозиторий и перейдите в его корневую директорию.

Установите проект и зависимости:

```bash
uv sync
```

## Запуск

Из корневой директории проекта:

```bash
uv run database
```

Для просмотра доступных команд в приложении введите:

```text
help
```

Для завершения работы:

```text
exit
```

## Используемые инструменты и библиотеки

- uv — управление проектом, зависимостями, окружением и сборкой.
- Ruff — статический анализ и проверка стиля кода.
- prettytable — отображение записей в табличном виде.
- prompt — ввод команд пользователя.
- json — чтение и запись данных в формате JSON, формирование ключей кэша.
- shlex — разбор команд управления таблицами.
- time — измерение времени выполнения функций.
- os — работа с файлами и директорией данных.

CRUD-команды разбираются строковыми операциями, а значения и условия —
функциями модуля `parser.py`.

## Хранение данных

Метаданные таблиц хранятся в файле:

```text
db_meta.json
```

Записи каждой таблицы хранятся отдельно:

```text
data/<имя_таблицы>.json
```

Пути отсчитываются от текущей рабочей директории.
Рекомендуется запускать приложение из корня проекта.

При отсутствии файла метаданных используется пустой словарь.
При отсутствии файла данных таблицы используется пустой список.

Локальные файлы базы данных, виртуальное окружение, кэши
и результаты сборки исключены из Git через `.gitignore`.

## Управление таблицами

| Команда | Описание |
|---|---|
| `create_table <имя> <столбец:тип> ...` | Создать таблицу |
| `list_tables` | Показать список таблиц |
| `drop_table <имя>` | Удалить таблицу после подтверждения |
| `info <имя>` | Показать схему таблицы и количество записей |
| `help` | Показать справку |
| `exit` | Завершить работу |

Поддерживаемые типы столбцов:

- `int` — целое число;
- `str` — строка;
- `bool` — логическое значение.

Столбец `ID:int` добавляется автоматически.
При явном указании `ID` допускается только тип `int`.

Пример:

```text
create_table users name:str age:int active:bool
```

## Правила ввода значений

- Строки заключаются в одинарные или двойные кавычки:
  `"Elina"` или `'Elina'`.
- Целые числа вводятся без кавычек: `25`.
- Логические значения вводятся как `true` или `false`.
- Значения при вставке указываются в порядке объявления столбцов.
- Все пользовательские поля обязательны.
- `ID` при вставке не указывается.
- Новый `ID` равен максимальному ID среди текущих записей плюс один.
  Для пустой таблицы используется `1`.
- Изменение столбца `ID` командой `update` запрещено.

## CRUD-операции

| Команда | Описание |
|---|---|
| `insert into <таблица> values (<знач1>, <знач2>, ...)` | Добавить запись |
| `select from <таблица>` | Получить все записи |
| `select from <таблица> where <столбец> = <значение>` | Получить записи по условию |
| `update <таблица> set <столбец> = <значение> where <столбец> = <значение>` | Обновить подходящие записи |
| `delete from <таблица> where <столбец> = <значение>` | Удалить подходящие записи после подтверждения |

Условие `where` поддерживает одно сравнение на равенство.
В `set` можно указать несколько изменений через запятую.

Команды `update` и `delete` требуют условие `where`.
Они применяются ко всем записям, соответствующим условию.

### Добавление

```text
insert into users values ("Elina", 25, true)
insert into users values ("Anna", 30, false)
```

### Выборка

Все записи:

```text
select from users
```

Записи по условию:

```text
select from users where active = true
```

### Обновление

```text
update users set age = 26 where name = "Elina"
```

Обновление нескольких полей:

```text
update users set age = 27, active = false where name = "Elina"
```

### Удаление записей

```text
delete from users where name = "Anna"
```

Перед выполнением приложение запросит подтверждение.

## Обработка ошибок

Декоратор `handle_db_errors` централизует обработку ожидаемых исключений:

- `KeyError` — например, отсутствие таблицы или столбца;
- `ValueError` — ошибки валидации и некорректные значения;
- `FileNotFoundError` — отсутствие файла, если исключение
  не обработано функцией работы с хранилищем.

При обработанном исключении выводится сообщение,
а обёрнутая функция возвращает `None`.

Пример ошибки типа:

```text
insert into users values ("Elina", "wrong", true)
```

Результат:

```text
Ошибка валидации: для столбца "age" ожидается тип int, получено значение 'wrong'.
```

Пример обращения к отсутствующему столбцу:

```text
select from users where unknown = 1
```

Результат:

```text
Ошибка: таблица или столбец 'unknown' не найден.
```

Для ошибок структуры команды предусмотрены отдельные сообщения.
Ожидаемые ошибки пользовательского ввода не завершают основной цикл.

## Подтверждение удаления

Декоратор `confirm_action(action_name)` запрашивает подтверждение
перед удалением таблицы или записей.

Пример:

```text
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]:
```

Для выполнения операции нужно ввести ровно `y`.
Любой другой ответ, включая пустую строку и `Y`, отменяет операцию.

При отмене выводится:

```text
Операция отменена.
```

Данные при отмене не изменяются.

## Измерение времени

Декоратор `log_time` измеряет время выполнения функций `insert`
и `select` с помощью `time.monotonic()`.

Пример:

```text
Функция select выполнилась за 0.000 секунд.
```

Время выводится с тремя знаками после запятой.
Длительность быстрой операции может округляться до `0.000`.

Измеряется выполнение функций в `core.py`.
Чтение и сохранение JSON-файлов выполняются отдельно в `engine.py`
и в этот замер не входят.

Если обёрнутая функция вызывает исключение,
сообщение о времени в текущей реализации не выводится.

Имя и описание обёрнутых функций сохраняются вручную,
без использования `functools`.

## Кэширование выборок

Функция `create_cacher()` возвращает внутреннюю функцию:

```python
cache_result(key, value_func)
```

Внутренняя функция хранит словарь кэша в замыкании.

При первом обращении по ключу вызывается `value_func()`,
а результат сохраняется. При повторном обращении возвращается
сохранённое значение.

В операции `select` ключ формируется из содержимого таблицы
и условия запроса. При изменении данных формируется другой ключ,
поэтому последующая выборка возвращает актуальный результат.

Перед сохранением результата в кэш и перед возвратом создаётся
новый список с копиями словарей записей. Это отделяет результат
от исходных данных и содержимого кэша.

Такое копирование подходит для поддерживаемых типов полей:
`int`, `str` и `bool`.

Ограничения реализации:

- кэш хранится только в памяти текущего процесса;
- чтение JSON-файлов не кэшируется;
- размер кэша не ограничен;
- старые результаты сохраняются до завершения процесса;
- формирование ключа и копирование записей требуют ресурсов,
  поэтому ускорение не гарантируется.
